# Заметки по лабораторной 02: Git и GitHub

## Три локальных состояния Git

- **Рабочая папка** — обычные файлы на диске, которые я открываю и правлю в редакторе. Git видит, что они изменились, но пока ничего не сохраняет.
- **Индекс (staging area)** — «корзина» для следующего коммита. Командой `git add` я кладу в неё именно те изменения, которые хочу сохранить вместе.
- **Коммит** — зафиксированный снимок проекта с автором, временем и сообщением. Коммит неизменяем и навсегда остаётся в истории.

Путь изменения: рабочая папка → (`git add`) → индекс → (`git commit`) → коммит.

## Git и GitHub — это не одно и то же

- **Git** — программа на моём компьютере, которая хранит историю изменений и работает без интернета.
- **GitHub** — сайт, где хранится удалённая копия репозитория (`origin`). Он нужен для резервной копии, совместной работы и сдачи работ. Данные туда попадают только после `git push`.

Сравнение состояний двумя командами:

- `git diff` (до `add`) сравнивает рабочую папку с индексом: показывает правки, которые ещё не добавлены.
- `git diff --staged` (после `add`) сравнивает индекс с последним коммитом: показывает, что попадёт в следующий коммит.
