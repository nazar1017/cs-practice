# Журнал воркшопа по Git (лабораторная 03)

Проект — `calc.py`: калькулятор, который читает два числа. Он развивался тремя коммитами: сложение, вычитание, умножение.

## Сравнение версий и поиск изменений

- `git log --oneline --stat` — список коммитов в одну строку с числом изменённых строк по каждому файлу. Увидел три коммита, в каждом изменён только `lab03/calc.py`.
- `git diff HEAD~2 HEAD -- lab03/calc.py` — разница между двумя состояниями файла. Показал, что за два последних коммита добавились функции `subtract` и `multiply` и две строки вывода.
- `git show HEAD~1` — один коммит целиком: сообщение, автор и изменения этого коммита.
- `git log -S"def" --oneline -- lab03/calc.py` — ищет коммиты, в которых изменилось число вхождений строки `def`. Нашёл все три коммита, потому что в каждом добавлялась новая функция.
- `git blame lab03/calc.py` — для каждой строки показывает коммит и автора, который её добавил последним.

Чем отличаются команды:

- `git diff` сравнивает два состояния и показывает только разницу, без сообщений.
- `git show` показывает один коммит с его сообщением и правками.
- `git log` показывает историю коммитов списком, правки — только с флагами `-p` или `--stat`.

## Восстановление файла

Я удалил из `calc.py` две строки вывода и не стал коммитить. `git status` показал файл как изменённый.

- `git restore lab03/calc.py` возвращает файл в состояние последнего коммита (точнее, из индекса). Мои несохранённые правки при этом пропадают без возможности вернуть: в Git их нет.
- `git restore --source=HEAD~2 lab03/calc.py` берёт файл из другого коммита (здесь из `HEAD~2`, старой версии без вычитания и умножения) и кладёт его в рабочую папку. `git diff` после этого показал разницу между старой версией и последним коммитом. Мои текущие правки тоже были бы затёрты.
- Второй `git restore lab03/calc.py` вернул файл к последнему коммиту: рабочая папка снова чистая.

Разница: обычный `restore` откатывает к последнему сохранённому состоянию, а `restore --source=...` достаёт версию из любого указанного коммита.
